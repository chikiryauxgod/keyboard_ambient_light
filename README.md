# Keyboard Ambient

Нативное приложение на C++20 и Qt 6: цвета выбранной области экрана управляют
подсветкой клавиатуры. Общий интерфейс для устройств VIA и OpenRGB, предпросмотр
захваченной области и отдельная цветовая калибровка для каждого устройства.

## Устройства

В главном окне нет выбора конкретного производителя или ручного ввода номера
контроллера: **Discover devices** находит устройства по именам.

| Драйвер | Что поддерживается |
|---|---|
| Preview | Предпросмотр без подключения к оборудованию |
| VIA RGB Matrix | Стандартный канал RGB Matrix прошивок VIA 12/13 |
| VIA RGB Light | Стандартный канал RGB Light прошивок VIA 12/13 |
| OpenRGB SDK | Устройства установленного сервера OpenRGB с режимом `Direct` и доступными LED |

Драйвер VIA больше не ограничен VID/PID одной модели. Перед первой записью он
проверяет версию протокола и читает исходные настройки выбранного RGB-канала.
Некоторые производители меняют протокол или не реализуют управление RGB через VIA;
такие устройства могут требовать отдельного драйвера. Для неизвестных VIA-устройств
показываются Matrix и RGB Light; выбрать нужно канал, который реализует прошивка.

Работа общего цвета подтверждена пользователем на **Epomaker Luma100 `342d:e506`
по 2,4 ГГц**. Это аппаратная проверка конкретной модели, а не ограничение приложения.
Беспроводная работа других моделей зависит от команд, которые пропускает приёмник.

Поддержка буквально каждой клавиатуры невозможна одним универсальным USB-запросом:
устройства с закрытым протоколом, без внешнего управления LED или с одноцветной
подсветкой имеют реальные аппаратные ограничения. OpenRGB даёт широкий набор
драйверов, прямой VIA работает независимо от него, дополнительные протоколы можно
подключать через `LightingOutput`. Сейчас одновременно выбирается одно устройство.

Оба драйвера отправляют **общий цвет**. Поклавишная геометрия и одновременная работа
с несколькими клавиатурами пока не реализованы. Наличие нескольких LED в OpenRGB
само по себе не задаёт физическое расположение клавиш.

## Платформы

| Платформа | Захват экрана | Статус |
|---|---|---|
| Linux / X11 | QScreen | Сборки Qt 6.4 и 6.8 проверены; первая версия работала у пользователя |
| Linux / Wayland | Qt Multimedia → системный ScreenCast-портал / PipeWire | Код собран с Qt 6.8; реальный Wayland-сеанс ещё не проверен |
| Windows | Qt Multimedia; QScreen в сборке без Multimedia | Есть код, CMake и CI-задание; выполнение на Windows ещё не проверено |
| macOS | Qt Multimedia; QScreen в сборке без Multimedia | Есть код, `.app`-сборка и CI-задание; выполнение на macOS ещё не проверено |

Для Wayland нужны **Qt 6.5+ Multimedia с FFmpeg**, PipeWire и работающий
`xdg-desktop-portal` с ScreenCast. Монитор выбирается в системном диалоге, потому что
Wayland не разрешает приложению незаметно выбрать его по индексу. Проценты области
относятся к монитору, выбранному в этом диалоге. Отказ/ошибка захвата показываются
в интерфейсе. На macOS требуется разрешение Screen Recording.

Релизный preset требует потоковый backend и рекомендует Qt 6.8. Разработка под
X11 по-прежнему возможна с системным Qt 6.4. CI-конфигурация для трёх ОС добавлена
в `.github/workflows/ci.yml` и переиспользуемом `build.yml`; она ещё не запускалась на удалённых runner-ах.

## Цвета и калибровка

1. Выбрать устройство и монитор. По умолчанию захватывается полоса X=0%, Y=80%,
   W=100%, H=17%: нижние 3% исключены, чтобы не захватывать панель задач.
2. Посмотреть **Captured screen region**: это реальная область, откуда берутся цвета.
   Держать окно программы вне этой области, чтобы его собственный предпросмотр
   не влиял на подсветку.
3. Выбрать **Dominant color**, чтобы сохранить преобладающий цвет сцены, или
   **Average**, чтобы смешать все цвета области. Тёмные пиксели можно исключить.
4. Во вкладке **Device color** отрегулировать RGB gain, насыщенность, гамму, сдвиг
   оттенка и яркость. Эти настройки сохраняются отдельно для выбранного устройства.
5. Для проверки выбрать `Test: red/green/blue/white/...` вместо экрана и нажать Start.
   Белый помогает проверить баланс каналов, основные цвета — оттенки прошивки/LED.
   Для смены источника сначала нажать Stop. Калибровку можно менять во время работы.

Слева показан извлечённый цвет, справа — рассчитанный выход после сглаживания,
калибровки и ограничения яркости. Это RGB-команда, а не измерение реального света.
Уменьшение изображения для анализа не смешивает исходные цвета. Помеченные цветовым
профилем изображения приводятся к sRGB; при отсутствии профиля предполагается sRGB.
HDR и аппаратная фотометрическая калибровка не реализованы.

Усреднение выполняется в линейном свете. Dominant использует гистограмму оттенков,
чтобы серые фоны не заглушали цветную часть сцены; для нейтральных сцен остаётся
обычное усреднение. Сглаживание зависит от прошедшего времени, а не количества кадров.
Клавиатурные LED и экран могут различаться даже при одинаковых RGB-значениях.

## Сборка на Ubuntu / Debian

```bash
sudo apt-get update
sudo apt-get install build-essential cmake pkg-config qt6-base-dev libhidapi-dev
cmake --preset dev
cmake --build --preset dev --parallel 3
ctest --preset dev
./build/keyboard-ambient
```

Qt 6.4 из Ubuntu подходит для X11. Для потокового захвата использовать Qt 6.8
с модулем Multimedia из Qt SDK и указать его путь через `CMAKE_PREFIX_PATH`.

### Права на прямое управление USB в Linux

GUI запускается обычным пользователем. Для Luma100:

```bash
sudo install -m 644 packaging/70-keyboard-ambient.rules /etc/udev/rules.d/70-keyboard-ambient.rules
sudo udevadm control --reload-rules
```

После этого переподключить донгл. Закрыть VIA перед управлением подсветкой.
Для другой VIA-клавиатуры выбрать устройство → **Connections → Export USB access
rule for selected device**. Экспортированное правило ограничено её VID/PID и номером
HID-интерфейса. Установить его аналогично примеру выше. Приложение не меняет права
системы самостоятельно. OpenRGB требует собственных прав на оборудование.

### OpenRGB

Запустить локальный SDK-сервер OpenRGB (обычно `127.0.0.1:6742`). Адрес можно
изменить в **Connections**. Нажать Discover devices, выбрать устройство по имени.
Устройства без Direct/LED показываются как недоступные для живых эффектов.
Обнаружение читает описание устройств и не меняет их подсветку. При изменении
списка устройств перед Start приложение проверяет идентичность выбранного контроллера.

### Windows и macOS

Нужны компилятор C++20, CMake, Qt 6 Widgets/Network/Multimedia и HIDAPI. CMake понимает
экспортируемую цель `hidapi::hidapi`, pkg-config и обычный поиск заголовков/библиотеки.
На Windows HIDAPI можно установить через vcpkg, на macOS — через Homebrew.
Пути Qt и HIDAPI передаются через `CMAKE_PREFIX_PATH` / vcpkg toolchain.

```bash
cmake --preset portable -DCMAKE_PREFIX_PATH=/path/to/Qt/6.8.3/platform
cmake --build --preset portable --parallel 3
ctest --preset portable
cmake --install build-release --config Release --prefix stage
```

Preset `portable` включает развёртывание Qt runtime. CPack создаёт ZIP/TGZ;
CI сохраняет переносимый архив с метаданными коммита и контрольной суммой для каждой ОС.
На Windows CMake включает HIDAPI DLL. На macOS создаётся `.app`. Подпись, notarization и полноценные
инсталляторы пока не настроены. Сборка, запущенная из этого workspace на Linux,
сама по себе не доказывает работоспособность на Windows/macOS.

### Ядро без Qt

```bash
cmake --preset core
cmake --build --preset core
ctest --preset core
```

## Архитектура и проверки

- `ambient_core`: обработка RGBA, средний/преобладающий цвет, горизонтальные зоны,
  RGB/HSV, калибровка, сглаживание, интерфейс `LightingOutput`. Не зависит от Qt.
- `ambient_devices`: обнаружение устройств, VIA/HIDAPI и OpenRGB/TCP, проверка
  возможностей и снимок/восстановление настроек. Весь I/O работает в отдельном потоке.
- `ambient_capture`: нормализованная область захвата, QScreen и Qt Multimedia.
  Для Wayland системный выбор экрана, для Windows/macOS — потоковый захват, если доступен.
- `main.cpp`: общий Qt Widgets интерфейс. Не содержит привязки к VID/PID Luma100.
  Для медленного устройства одновременно ожидает не более одного кадра.

Тесты: извлечение цвета и калибровка, временное сглаживание, геометрия области,
OpenRGB с локальным тестовым TCP-сервером (обнаружение, возможности, порядок пакетов,
восстановление, отказ при смене устройства), offscreen GUI с тестовым красным в Preview.
Тесты не отправляют команды реальной клавиатуре. На Linux собраны варианты Qt 6.4
и Qt 6.8 с Multimedia; фактический захват Wayland и другие ОС требуют отдельных проверок.
Все C++ юнит-тесты переведены на GoogleTest и регистрируются в CTest по отдельности.
Проверяются также ошибки протоколов VIA/OpenRGB и освобождение HID-ресурсов.
Linux release установлен в отдельный каталог и проверяется с собственными Qt/HIDAPI библиотеками.
Готовый локальный архив: `dist/KeyboardAmbient-0.2.0-Linux-x86_64.tar.gz`.

## CI/CD и релизы

CI запускается на **push, pull request, merge queue и вручную**: сборки Linux,
Windows и macOS, GoogleTest, GUI smoke, ASan/UBSan, coverage и actionlint.
Релиз запускается отдельно: **Actions → Release → Run workflow → tag**, например
`v0.3.0`. После успешных сборок всех ОС Action создаёт Git-тег и GitHub Release
с архивами и `SHA256SUMS`. Для существующего тега собирается его точный коммит;
опубликованный релиз не перезаписывается. Есть опции draft и prerelease.

Подробные команды, права и поведение при ошибках: [CI и выпуск](docs/ci-release.md).
Результаты локального прогона: [59 проверок и coverage](docs/validation.md).

Stop и штатный выход восстанавливают исходную подсветку. Команды сохранения в память
устройства не отправляются. Отключение приёмника или принудительное завершение процесса
могут помешать восстановлению. Автоматическое переподключение пока не реализовано.
Снимки экрана обрабатываются локально: не сохраняются и не отправляются по сети.
OpenRGB получает только цветовые команды. `--smoke-test --snapshot <path>` сохраняет
только изображение собственного тестового окна по явному запросу.
